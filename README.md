# 文物库房环境监测后端

面向博物馆文物保护部门的 Node.js 环境监测服务：接收温湿度传感器读数（含设备时间与网关采集时间），
按库房分区与文物敏感等级生成去重告警，支持值守员确认、转派、现场复测与关闭，保留告警期间全部原始数据。

核心能力：

- **可信时间优先**：所有窗口、去抖、升级判定只用采集时间 `collectedAt`；设备时钟快/慢在结果中明确标出
  （含与校准基线的偏差、未校准、校准过期）。
- **分区去重告警**：告警维度为 `分区 + 指标`，同分区多台设备连续越限并入同一条告警；支持批量补传幂等，
  重复读数与历史补传**不重放通知**。
- **完整生命周期**：确认、转派、现场复测（带证据）、关闭；未确认超时、高敏感分区久未复测、复测后久未闭环
  都会自动升级，每次升级记录原因、触发器与截止时间。
- **静默时段与值班表**：静默时段只延后短信、不阻断告警；支持跨午夜静默窗与跨午夜班次。
- **崩溃恢复**：状态与所有截止时间落盘，进程重启后定时检查与未发送通知按原截止时间继续处理。

## 运行

需要 Node.js 22 或更高版本。

```bash
npm ci
npm start        # 默认 0.0.0.0:8000
npm test         # node --test
```

环境变量：`PORT`、`HOST`、`DATA_DIR`（状态落盘目录，默认 `./.data`）、
`REFERENCE_DIR`（参考数据目录，默认 `./reference`）。

也可以使用 `docker compose up --build`（compose 已配置 `.data` 持久化卷）。

参考数据（可按现场替换）：`reference/sensors.json`（传感器清单）、
`reference/calibrations.json`（时钟校准记录）、`reference/zones.json`（分区阈值与静默时段）、
`reference/contacts.json`（通知联系人）、`reference/roster.json`（值班表）、
`reference/settings.json`（去抖/超时/补传窗口等参数）。

健康检查 `GET /health` 仅表示进程存活，不代表任何业务流程已完成。
